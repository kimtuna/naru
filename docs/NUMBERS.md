# NUMBERS — 실측으로 얻은 값만

> **이 파일은 혼자 선다.** 다른 문서를 안 봐도 읽힌다.
>
> **값보다 「조건」이 중요하다.** 아래 값은 전부 어떤 기계 · 어떤 엔진 버전 위에서
> 잰 것이다. 조건이 다르면 그대로 못 쓰고, **비율로 환산해도 안 되는 것이 있다.**
>
> 값을 고치려면 **새로 재고 조건을 같이 적는다.** 「passed」는 증거가 아니다.

## 1. 화면 (2026-09-13 실측)

**조건: `stretch/mode=viewport` + `scale_mode=integer` + `aspect=keep`, 창 override 1920×1080**

실제로 창을 띄워서 잰 값이다 (`scripts/main.gd` 가 찍는다):

```
VIEWPORT 960 x 540
WINDOW   1920 x 1080
SCALE    2.00 x
```

| 값 | 무엇 | 왜 그 값인가 |
|---|---|---|
| **960 × 540** | 논리 해상도 (= 보이는 월드 범위) | **1080p 정수 2배 · 4K 정수 4배.** 소수 배율은 도트 하나를 화면에서 어떤 건 1px, 어떤 건 2px 로 만들어 걸을 때 얼룩이 흐른다 |
| **1920 × 1080** | 창 크기 | 논리 화면을 정확히 2배로 늘려 붙인다 |
| **2.00 ×** | 실측 배율 | 정수다 |
| **20 × 11.25 칸** | 보이는 타일 수 | 타일 48px 기준. `test_visible_tiles_at_48px` 가 강제한다 |

**대가**: UI 도 960×540 좌표계에서 만들어야 하고, 폰트가 통째로 2배로 늘어나므로
**비트맵 픽셀 폰트가 필요하다** — 기본 폰트는 늘리면 뭉갠다.

### 실측 게이트 `tools/tests/measure_view.gd` (2026-09-14 실측)

위 표는 `test_project_settings.gd` 가 **project.godot 의 글자**를 읽어 강제한다.
글자가 맞아도 실행 중에 카메라 줌이나 창 크기를 만지면 눈에 보이는 칸은 달라진다 —
그래서 **실제 창을 띄워** 다시 잰다 (`check.sh tests` 가 `--headless` 없이 부른다).

```
VIEW 논리 960x540 · 창 1920x1080 · 배율 2.00x · 카메라 1.00x · 타일 48px · 보이는 칸 20.00 x 11.25
VIEW ok (드라이버 macOS · 프레임 5)
```

- 배율은 나눗셈이 아니라 **`root.get_final_transform()`** 에서 잰다.
- 보이는 칸은 **`get_canvas_transform()`** 으로 월드 좌표로 환산해서 잰다 —
  카메라 줌이 곧 시야 이득이라 여기를 막아야 한다 (BACKLOG P1 「줌 없음」).

**대조군 2종** (`redteam.sh` 에 박아 뒀다):

| 일부러 깨뜨린 것 | 단위 검사 | 화면 실측 |
|---|---|---|
| 카메라 `zoom` 을 (2,2) 로 | (2026-09-13: `18 passed`) | **잰 값 보이는 칸 10.00 x 5.62** ✅ |
| 실행 중 `window_set_size(1600, 900)` | `18 passed, 0 failed` | **잰 값 창 1600x900 · 배율 1.00x** ✅ |

두 번째가 정수 배율의 성질을 그대로 보여준다: 1600/960 = 1.66 이 아니라 **1** 로 떨어진다.

**첫 줄은 바퀴 8 에서 겨눌 곳이 바뀌었다.** 그때는 `main.tscn` 에 카메라를 하나 덧붙였는데,
진짜 카메라가 생긴 뒤로는 **먼저 트리에 들어온 플레이어의 카메라가 화면을 잡는다(선착순)** —
덧붙인 카메라는 아무 일도 안 한다. **가짜 대조군이 될 뻔한 자리다.** 지금은 `player.tscn` 의
그 카메라의 줌을 직접 건다. 대신 단위 검사(`test_camera_zoom_is_one`)도 같이 잡으므로,
「단위는 초록인데 실측만 잡는」 쪽은 8절의 **실행 중 줌**이 맡는다.

## 2. 격리 — **macOS 는 XDG 를 무시한다** (2026-09-13 실측)

**이걸 안 재고 넘어갈 뻔했다.** `XDG_DATA_HOME` 등을 설정해두고 「격리했다」고 믿는 것이
정확히 가짜 게이트다.

| 방법 | `user://` 가 실제로 간 곳 | 홈의 Godot 디렉터리 |
|---|---|---|
| `XDG_*` 만 설정 | `~/Library/Application Support/Godot/app_userdata/Naru` | **mtime 이 실행 시각으로 갱신됨** ❌ |
| **`HOME` 을 돌린다** | `.godot-home/Library/Application Support/Godot/app_userdata/Naru` | **mtime 안 바뀜** ✅ |

- 그래서 `tools/loop/godot.sh` 는 **`HOME` 자체를 프로젝트 안으로 돌린다.**
  `XDG_*` 도 같이 두는 것은 리눅스에서 도는 경우를 위해서다.
- **격리는 설정이 아니라 「입구」로 지켜진다.** `test_isolation.gd` 가
  `OS.get_user_data_dir()` 이 프로젝트 안인지 재므로, **`godot.sh` 를 우회한 실행은
  그 자리에서 빨개진다.** 실측:

  ```
  FAIL test_isolation.gd :: test_user_data_is_project_local
       — 잰 값: /Users/tuna/Library/Application Support/Godot/app_userdata/Naru
  ```

## 3b. 화면 캡처 (2026-09-13 실측)

**`screencapture` 는 못 쓴다** — macOS 화면 기록 권한에 막힌다
(`could not create image from display`). 무인 루프가 권한 대화상자를 넘길 방법이 없다.

**Godot 자신의 프레임버퍼를 읽는다** (`tools/qa/shot.gd`). 권한이 필요 없고,
화면에 보이는 것이 아니라 **게임이 그린 것**을 읽으므로 다른 창이 겹쳐도 상관없다.

| 방식 | 결과 |
|---|---|
| `--headless` + 뷰포트 텍스처 | **안 된다** — 렌더러가 더미라 텍스처가 빈다 (출력 없음) |
| **창을 띄우고 뷰포트 텍스처** | **된다** — `SHOT 960x540 색 3개 가장 넓은 한 색 50.0%` |

- 그래서 `tools/loop/shot.sh` 는 `--headless` 를 **쓰지 않는다.** 창이 잠깐 떴다 사라진다.
- **「저장됨」은 증거가 아니다** — 크기 · 색 수 · 가장 넓은 한 색의 비율을 같이 찍는다.
  `--max-flat <퍼센트>` 로 「거의 단색인 화면」을 빨갛게 만들 수 있다.
- 대조군: 상한 40% → 빈 씬(50%)이 잡힘 / 없는 씬 → `SHOT ERROR` / 헤드리스 → 출력 없음.

### 섬 모양은 운이 아니라 **부등식**이다

| 보장 | 왜 참인가 |
|---|---|
| 테두리는 **항상 물** | 감쇠 `FALLOFF_GAIN 1.25` > 잡음 최대 `1.0` → 높이 ≤ -0.25 < 해수면 0.30 |
| 한가운데는 **항상 땅** | 잡음 바닥 `NOISE_FLOOR 0.35` > 해수면 `SEA_LEVEL 0.30`, 중심 감쇠 ≈ 0 |

씨앗을 몇 개 뽑아 봐서 「되더라」가 아니라 상수끼리의 부등식이다.
**상수를 만지면 이 두 줄부터 다시 계산해야 한다** — 검사(`test_border_is_always_water`,
`test_spawn_is_always_land`)가 여러 씨앗으로 지키지만, 검사는 표본이고 위 두 줄은 증명이다.

| `CONTRAST` | 2.5 | **1.0 이면 해안선이 동그란 덩어리가 된다.** 실제로 그렇게 나와서 올렸다 |

## 7. 충돌 (2026-09-14 실측)

**조건: `scripts/world_collide.gd` · Godot 4.7.2 · macOS M5 Pro · 헤드리스 ·
물리 60 Hz · 씨앗 20260914 · 메인 씬을 통째로 띄워 잼**

| 값 | 무엇 |
|---|---|
| **22.0 px** | 몸 반폭(`HALF`). 몸 44×44 가 48 타일 안에서 **양옆 2px 씩 남는다** |
| **0.01 px** | 벽에 붙일 때 남기는 틈(`EPS`). 0 이면 붙은 칸이 겹친 칸으로 읽혀 다음 프레임이 흔들린다 |
| **169.71 px/s** | 해안을 탈 때의 세로 속력 = 240 / √2. **벽에 붙어도 안 줄인다** |
| **3.302 µs** | 「이 칸이 막나」 한 번 (10만 회 330.2 ms · 막힘 67.7%). 한 틱에 네 번쯤 묻는다 |

**몸이 타일보다 좁아야 하는 이유**: `HALF` 가 타일 반(24)과 같으면 폭 1칸(48px) 통로에서
부동소수 한 톨에 걸려 낀다. `22 < 24` 는 검사(`test_body_is_narrower_than_a_tile`)가 지킨다.

### 미끄러짐은 **축을 따로 푸는 것**에서 나온다

x 를 풀고 y 를 푼다 — 막힌 축만 죽고 나머지는 그대로 간다.
「벽에 닿았으니 통째로 정지」가 아니고, 남은 몫을 다시 정규화하지도 않는다.
**물리 엔진을 안 쓴다**: 65536칸에 정적 몸을 세울 수 없고, 창 주변만 세우면 결과가
「지금 무엇이 세워져 있나」에 달린다. 격자에 대고 풀면 **같은 입력이 언제나 같은 자리**다
(GDD D-1 서버 재현성 · C-4 원정 보고 검증).

### 실측 게이트 `tools/tests/measure_collide.gd` (2026-09-14 실측)

`check.sh tests` 가 `WORLD` 뒤에 부른다. **메인 씬을 통째로 띄운다** — 플레이어 씬만
띄우면 `main.gd` 의 배선이 안 잡힌다. 씨앗에서 **곧은 남북 해안**(땅 4칸 × 7줄 + 옆은 바다)을
스폰에서 가까운 순으로 찾아, 활주로 3칸에서 걸어 부딪힌다.

```
COLLIDE 해안 월드칸 (229, 122) · 스폰에서 101.2칸 · 활주로 3칸 · 바다 면 11040.00 px
COLLIDE 바다로 직진       x 11017.99 (바다 면 11040.00) · 세로    0.00 px/s · 1.0035 s 동안 (145.9902, 0.0)  ok
COLLIDE 해안 미끄럼       x 11017.99 (바다 면 11040.00) · 세로  169.70 px/s · 1.2001 s 동안 (145.9902, 203.6602)  ok
COLLIDE 질의 100000회 330.2 ms (1회 3.302 µs · 막힘 67.7%)
COLLIDE ok (구간 2 · 몸 반폭 22 · 틈 0.01 · 물리 60 Hz)
```

**2026-09-14 카메라(8절)와 함께 다시 쟀다.** 값이 5376 → 11040 으로 옮겨간 것은 물리가
아니라 **좌표계**다: 이제 화면 칸 = 월드 칸이라 해안 칸 230 이 그대로 230 × 48 = 11040 px 다.
멈춘 자리 **11017.99 = 11040 - 22 - 0.01** 이다. 세 가지를 같이 본다:
① 바다 면 앞에 서는가 ② **몸이 바다에 걸치지 않는가**(좌표만 맞고 반 칸 잠기는 경우가 있다)
③ 옆으로 가려던 몫이 살아 있는가(169.71 ±5).

### 화면 칸 ≠ 월드 칸 — **사라진 값** (2026-09-14 · 바퀴 8)

바퀴 7 에는 `main.gd` 에 `tile_offset = (118, 123)` 이 있었다. 카메라가 없어서 플레이어가
화면 안(504, 264 = 화면 칸 10,5)에 있어야 했는데 섬의 스폰은 월드 한가운데(128,128)였기
때문이다. **카메라가 오면서 그 값은 0 이 아니라 아예 없어졌다** (8절):
플레이어는 스폰 칸의 한가운데 (6168, 6168) 에 그냥 서 있다. `solid_from_seed` 의 이동량
인자와 `main.gd` 의 `screen_of()` 도 같이 지웠다 — **화면 칸 = 월드 칸**이다.

### 대조군 — P1-5 로 새로 넣은 3종 (2026-09-14 실측)

| 일부러 깨뜨린 것 | 단위 검사 53개 | 결과 |

## 8. 카메라 (2026-09-14 실측)

**조건: `scenes/player.tscn` 의 `Camera2D` · Godot 4.7.2 · macOS M5 Pro · 헤드리스 ·
물리 60 Hz · 씨앗 20260914 · 메인 씬을 통째로 띄워 네 방향으로 걸으며 잼**

| 값 | 무엇 |
|---|---|
| **0.0000 px** | 걷는 내내 플레이어가 화면 중심에서 벗어난 **최대** 거리 (표본 294) |
| **1.00 x** | 캔버스 변환의 줌. **보이는 칸 20.00 x 11.25 — 1절과 같은 값이다** |
| **(6168, 6168)** | 스폰 자리 = 칸 (128,128) 의 한가운데. 화면으로는 **(480, 270)** = 정확히 한가운데 |
| **[P: (5688, 5898), S: (960, 540)]** | 스폰에서 보이는 월드 범위(px). 논리 화면과 크기가 같다 = 줌이 없다 |

### 카메라는 **코드가 아니라 부모-자식**이다

`Camera2D` 를 플레이어 씬 안에 둔다. 매 프레임 `camera.position = player.position` 을
쓰지 않는다 — 그건 물리(60Hz)와 그리기 사이에 **한 틱 뒤처질 자리**를 만들고,
프레임률에 따라 뒤처지는 양이 달라진다. 실측 편차가 **0.0000 px** 인 것이 그 값이다.

같은 이유로 `position_smoothing` 을 끈다. 부드럽게 따라오는 화면은 예쁘지만
**「같은 입력 = 같은 화면」이 아니다.** 켜 보면 최대 편차가 **82.10 px** 로 벌어진다(아래 표).

### 줌은 **1 이다** — 해상도가 시야 이득이 되면 안 된다

창이 큰 사람이 더 멀리 보면 그건 설정이 아니라 **유리함**이다 (BACKLOG P1 「줌 없음」).
그래서 두 군데서 막는다: 씬에 박힌 글자(`test_camera_zoom_is_one`)와
**실행 중의 캔버스 변환**(`measure_camera.gd` · `measure_view.gd`).

### 사라진 값 — `tile_offset`

바퀴 7 의 `tile_offset = (118, 123)` 이 없어졌다. **화면 칸 = 월드 칸**이다 (7절).
`WorldCollide.solid_from_seed` 의 이동량 인자와 `main.gd` 의 `screen_of()` 도 같이 지웠다.

임시 격자도 **월드에 고정**으로 바꿨다(`main.gd` 의 `visible_world_rect()`).
화면에 고정돼 있으면 **카메라가 따라가는지 사람 눈에 안 보인다** — 플레이어가 격자 위에서
얼어붙은 것처럼 보인다. `SHOT 960x540 · 색 4개 · 가장 넓은 한 색 50.0%`.

### 실측 게이트 `tools/tests/measure_camera.gd` (2026-09-14 실측)

`check.sh tests` 가 `COLLIDE` 뒤에 부른다. 헤드리스로 된다 — 캔버스 변환은 창 없이도 돈다.
네 방향으로 0.5초씩 걸으며 **매 프레임** 잰다.

```
CAMERA 스폰 월드 (6168.0, 6168.0) · 화면 (480.0, 270.0) · 보이는 월드 [P: (5688.0, 5898.0), S: (960.0, 540.0)]
CAMERA 최대 편차 0.0000 px · 걸은 거리 484.00 px · 줌 1.00x · 보이는 칸 20.00 x 11.25 · 표본 294
CAMERA ok (구간 4 × 0.5 s · 허용 편차 0.50 px · 물리 60 Hz)
```

- **판정은 「화면 안에 있나」가 아니라 「중심에서 몇 px 벗어났나」다.** 카메라가 아예 없어도
  플레이어가 화면 밖으로 나가는 데는 시간이 걸린다 — 느슨한 판정은 그 사이를 놓친다.
- **걸은 거리(484.00 px)를 같이 잰다.** 안 움직이면 「늘 한가운데」는 공짜다.
- 허용 편차 **0.50 px** 는 넉넉한 값이 아니라 **0 이어야 하는 값에 준 여유**다.
  끌려오는 카메라는 첫 표본이 이미 4.00 px 로 잡힌다(아래 ③).

### 대조군 — P1-6 으로 새로 넣은 3종 (2026-09-14 실측)
