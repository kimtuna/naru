# JOURNAL — 바퀴 일지

> **한 바퀴에 무슨 일이 있었나.** 「무엇을 만들었나」보다 **「무엇이 막았고, 왜 그랬고,
> 그래서 무엇을 바꿨나」**를 남긴다. 몇 바퀴 뒤의 나에게 가장 비싼 정보가 그거다.
>
> **계속 쌓이는 파일이다.** 그래서 **세션은 이 파일을 읽지 않는다** — `GOTCHAS.md` 와 같은 층이다.
> 사람과 대시보드(`docs/index.html`)만 읽는다.

## 쓰는 법 — 형식을 지킨다 (기계가 파싱한다)

한 바퀴가 끝나면 **맨 위에** 절을 하나 덧붙인다. 최신이 위다.

```markdown
## 바퀴 N · <항목 이름>
- 날짜: YYYY-MM-DD
- 결과: 초록 | 빨강 | 멈춤
- 문제: <이번 바퀴에 실제로 막힌 것. 없으면 「없음」>
- 원인: <왜 그랬나. 증상이 아니라 이유>
- 고친 것: <무엇을 어떻게 바꿨나. 파일 이름을 적는다>
- 바꾼 결정: <설계·규칙이 바뀌었으면. 없으면 「없음」>
- 잰 값: <숫자 + 조건. 「passed」는 증거가 아니다>
- 남긴 것: <다음으로 넘긴 것 / 사람이 정할 것. 없으면 「없음」>
- 채점: <드라이버가 찍는다. 손대지 마라>
- 비용: <드라이버가 찍는다>
- 커밋: <드라이버가 찍는다>
```

- **`문제`·`원인`·`고친 것`·`남긴 것` 은 세션이 채운다.** 사람의 판단이 들어간 줄이다.
- **`날짜`·`결과`·`채점`·`비용`·`커밋` 은 드라이버가 찍는다** (`tools/loop/journal.sh stamp`).
  세션이 「됐습니다」라고 쓴 것이 아니라 **채점자(`run-contract.sh`)가 쓴 `results.json`** 이 들어간다.
- **세션이 `문제`·`원인`·`고친 것`·`남긴 것` 을 비워 두면 드라이버가 멈춘다**
  (`journal.sh check`). 만든 것만 적고 막힌 것을 안 적으면 일지가 커밋 로그와 같아진다.
- **문제가 없었어도 절을 뺀 채로 넘어가지 않는다.** `문제: 없음` 이라고 적는다 —
  빈 바퀴와 안 적은 바퀴는 다르다.
- 사람이 직접 개입한 세션은 `## 사람 · <제목>` 으로 적는다. 바퀴 번호를 쓰지 않는다.
